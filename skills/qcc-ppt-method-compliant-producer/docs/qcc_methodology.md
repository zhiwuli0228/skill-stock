# QCC 标准方法学（本 Skill 的判定基线）

本文件是 `qcc-ppt-method-compliant-producer` 的方法学正本。所有页面契约、合规协议、
验收清单与合规检查脚本都以本文件为准。方法名词必须对应到真实的输入、分析动作、
输出产物与判定标准，**仅出现名词不算合规**。

## 1. 标准十步法

品管圈活动按以下十个步骤推进，每一步都必须有：输入、分析方法、输出产物、判定标准。

| # | 步骤 | 输入 | 分析方法 / 工具 | 输出产物 |
|---:|---|---|---|---|
| 1 | 主题选定 | 现场问题、上级政策、圈员意见 | 头脑风暴、亲和图、**主题评价矩阵**（评价维度 + 权重 + 评分 + 排序 + 选定理由） | 候选主题清单、主题评价表、选定主题及理由 |
| 2 | 活动计划拟定 | 选定主题、活动周期 | 甘特图、PDCA 阶段划分 | 活动计划甘特图（阶段/周次/负责人） |
| 3 | 现状把握 | 现状流程、历史数据 | 现状流程图（as-is）、**查检表设计**（判定标准/收集期间/样本量）、数据汇总、**层别分析**、**柏拉图**（累计百分比 + 80% 改善重点） | 现状流程图、查检表、汇总数据、柏拉图、改善重点结论 |
| 4 | 目标设定 | 现况值、改善重点、圈能力 | 目标值计算：目标值 = 现况值 −（现况值 × 改善重点 × 圈能力） | 目标值、目标柱状图、目标合理性说明 |
| 5 | 解析 | 改善重点、现场事实 | 特性要因图（4M1E：人/机/料/法/环/测）、**要因评价**（评分/投票筛选要因）、**真因验证**（回到现场用查检表/柏拉图/数据验证，未通过必须回退） | 鱼骨图、要因评价表、真因验证数据与结论 |
| 6 | 对策拟定 | 已验证真因 | **对策评价矩阵**（可行性/效益性/经济性/圈能力）、对策群组/系统图、**5W1H**、对策↔真因对应 | 对策评价表、5W1H 对策表、对策↔真因映射表 |
| 7 | 对策实施与检讨 | 采纳对策 | PDCA 分阶段实施、过程数据跟踪、困难与调整 | 实施计划与记录、跟踪数据、困难与调整说明 |
| 8 | 效果确认 | 实施后数据 | 有形成果：改善前后对比、柏拉图对比、**目标达成率**、进步率；无形成果：圈员能力雷达图 | 改善前后对比图、目标达成率、进步率、无形成果雷达图 |
| 9 | 标准化 | 有效对策 | 标准化文件（作业标准书/流程图/制度表单）、纳入日常管理（谁/何时/如何稽核）、教育训练与推广 | 标准化文件清单、稽核方式、培训与推广计划 |
| 10 | 检讨与改进 | 全流程记录 | 活动检讨（优点/不足）、残余问题、下期主题 | 检讨与改进报告、下期主题 |

## 2. 工具归位表

| 工具 | 正确归属 | 常见误用 |
|---|---|---|
| 头脑风暴、亲和图 | 步骤 1 主题选定（辅助发散与归类） | 用它们替代主题评价，直接“选出”主题 |
| 查检表（检查表） | 步骤 3 现状把握（数据收集） | 放到主题评审阶段当评价表使用 |
| 现状流程图（as-is） | 步骤 3 现状把握 | 用子流程/目标流程图替代现状流程 |
| 柏拉图 | 步骤 3 现状把握、步骤 8 效果确认 | 只有 80% 标记，没有类别频次与累计百分比 |
| 特性要因图（鱼骨图） | 步骤 5 解析 | 画完鱼骨图就当作找到根因 |
| 矩阵图 / 要因评价 | 步骤 5 解析（筛选要因） | 用要因评价替代真因验证 |
| 真因验证 | 步骤 5 解析 | 只写“疑似原因/验证方法/结果”文字，没有数据 |
| 对策评价矩阵 | 步骤 6 对策拟定 | 只有 5W 表格，没有评价与取舍 |
| 5W1H | 步骤 6 对策拟定、步骤 7 实施 | 只写 5W，缺 How（如何做/做到什么程度） |
| 甘特图 / PDPC | 步骤 2 活动计划 | 用目录页代替活动计划 |
| 雷达图 | 步骤 8 效果确认（无形成果） | 只报有形成果，忽略圈员成长 |
| 作业标准书/制度表单 | 步骤 9 标准化 | 只列“标准化清单”，没有文件本体 |
| SIPOC | 过程管理/六西格玛工具 | 用它替代 QCC 现状把握的查检表与柏拉图 |

## 3. 判定标准（每一步的合规条件）

### 步骤 1 主题选定

- 候选主题 ≥ 2 个。
- 评价维度 ≥ 3 个（如：上级政策、重要性、迫切性、可行性、圈能力、效益性）。
- 每个候选主题都有评分，且有排序或选定结论。
- 缺任一条件 → WEAK；以“待补充”占位 → INCOMPLETE。

### 步骤 2 活动计划拟定

- 覆盖 PDCA 四个阶段或十步法阶段（≥ 4 个阶段）。
- 有时间轴（周次/日期）与负责人。
- 缺时间或负责人 → WEAK。

### 步骤 3 现状把握

- 有现状流程图（as-is），流程步骤 ≥ 3。
- 查检表包含：判定标准、收集期间、样本量。
- 有数据汇总：问题类别 ≥ 3，每类有频次/数量。
- 有层别维度（按人/机/料/法/环/测或时段/班别等）。
- 柏拉图：类别按降序排列，含频次与累计百分比，标出 80% 改善重点，并给出关键少数结论。
- 任一数据缺失 → INCOMPLETE（不得用图形外壳冒充）。

### 步骤 4 目标设定

- 有现况值（数值 + 单位）。
- 有改善重点（%）。
- 有圈能力（%）。
- 有目标值（数值），并能看到计算关系（公式或分步计算）。
- 有目标柱状图或对比图与合理性说明。
- 缺参数 → WEAK；参数为占位 → INCOMPLETE。

### 步骤 5 解析

- 鱼骨图覆盖 4M1E 中 ≥ 4 个维度，主干问题明确。
- 要因评价：对候选要因评分/投票并筛出要因。
- 真因验证：每条要因都有数据来源（查检表/样本/现场数据）、验证结果与结论。
- 验证不通过的要因必须有回退说明，不得直接进入对策。
- 无数据验证 → INCOMPLETE。

### 步骤 6 对策拟定

- 对策 ≥ 3 条。
- 对策评价维度 ≥ 3（可行性/效益性/经济性/圈能力等）并有评分与取舍。
- 5W1H 六要素齐全：What / Why / Who / Where / When / How。
- 每条对策映射到至少一条**已验证真因**。
- 缺真因映射 → WEAK；无已验证真因 → INCOMPLETE。

### 步骤 7 对策实施与检讨

- 有分阶段实施记录（阶段/时间/责任人/进展）。
- 有过程数据跟踪（数量或比例）。
- 有困难与调整说明。

### 步骤 8 效果确认

- 有形成果：改善前值、改善后值、目标达成率（%）、进步率（%）。
- 有改善前后柏拉图或对比图。
- 无形成果：圈员能力评分/雷达图。
- 缺目标达成率或缺无形成果 → WEAK；只有标题无数据 → INCOMPLETE。

### 步骤 9 标准化

- 标准化文件清单，含文件类型（作业标准书/流程图/制度/表单）。
- 纳入日常管理：执行人、稽核频率、稽核方式。
- 教育训练与推广安排。

### 步骤 10 检讨与改进

- 活动优点与不足。
- 残余问题。
- 下期主题或持续改进方向。

## 4. 数据缺失处理

1. 缺数据时保留方法页结构，但必须显式标注 `待补充` / `待验证` / `示例结构`。
2. 方法页结构保留不等于合规：只要该步的关键数据缺失，整体判定为 **INCOMPLETE**。
3. 严禁编造业务数据或结论。

## 5. 与旧版（v4.x）的差异

| 旧版 v4.x | 新版 v5.0 |
|---|---|
| 方法链：头脑风暴→亲和图→检查表 / SIPOC→柏拉图→子流程图 / 鱼骨图+矩阵图→根因验证 / 5W / 列表 | 标准十步法，工具各归其位 |
| 合规 = 方法名词出现在标题/正文 | 合规 = 步骤输入、分析证据、输出、判定标准四要素成立 |
| SIPOC 替代现状把握 | SIPOC 降为可选业务背景参考；现状把握使用流程图 + 查检表 + 层别 + 柏拉图 |
| 无主题评价、活动计划、目标设定 | 三者均为必选步骤 |
| 根因验证仅为表格 | 要因评价 → 真因验证（数据验证 + 未通过回退） |
| 仅有 5W | 对策评价矩阵 + 5W1H + 对策↔真因映射 |
| 无效果确认 | 有形成果 + 无形成果（雷达图） |
| 标准化清单 | 标准化文件 + 日常稽核 + 教育训练 |
| 无检讨与改进 | 检讨与改进 + 下期主题 |
