# QCC Page Contract (v5.0)

## 1. 目的

本契约把标准十步法（`docs/qcc_methodology.md`）落到页面上：每一页不仅有方法名称，
还必须承载该步的输入、数据证据与结论。页面标题是审查入口，但不是合规本身。

## 3. 标题规则

方法页统一使用 `阶段｜方法` 形式，例如：

```text
主题选定｜主题评价
现状把握｜柏拉图：识别关键 80% 改进项
解析｜真因验证
对策拟定｜5W1H
效果确认｜有形成果
```

禁止用通用标题替代方法页：`问题分析`、`现状说明`、`原因分析`、`改进措施`、`成果展示`。

## 4. 页面合并规则

默认不合并必需页面。确需压缩页数时，必须同时满足：

1. 标题显式写出所有被合并的方法名；
2. 每个方法保留可识别的形态与必备字段；
3. 渲染后文字与图表不重叠、不溢出。

## 5. 缺数据规则

缺数据时保留页面结构，显式标注缺什么：

```text
现状把握｜柏拉图：识别关键 80% 改进项
待补充：问题类别、各类频次、收集期间与样本量。
当前页保留柏拉图结构，补齐数据后生成正式图表。
```

缺数据页在合规检查中判为 `INCOMPLETE`，整体 `NON-COMPLIANT`。

## 6. 与旧版（v4.x）的主要差异

- 新增：主题评价、活动计划、目标设定、效果确认（有形成果+无形成果）、检讨与改进。
- 移出：SIPOC 不再作为现状把握的必需方法（只可作背景参考）。
- 归位：查检表从“主题评审”移到“现状把握”。
- 深化：鱼骨图之后必须经过要因评价与真因验证；5W 升级为 5W1H + 对策评价 + 真因映射。

## 7. 模板使用规则（v5.0 补充）

### 各方法的最低形态要求（v5.6.3 补充）

「方法名词在场」不算方法成立。每一页必须呈现该方法的**标准形态**；下面列出被实际
验收打回过的形态，以及正确写法。机器可判的部分由 `check_qcc_method_compliance.py`
对应规则强制（规则名见括号）。

| 方法 | 反例（判 WEAK） | 正确形态 | 对应规则 |
|---|---|---|---|
| 主题评价矩阵 | 把 5 个维度压成一格「5 / 5 / 5 / 4 / 4」 | **维度成列或成行**，逐维度评分可见 + 权重/评分规则 + 总分与排序 | 评价矩阵逐维度可见 |
| 活动计划甘特图 | 只有 4 条 P/D/C/A 阶段横条 | 行＝十步法工作项目（≥6）、时间轴、负责人、计划条 + 实际条、进度偏差 | 工作项目 ≥6 |
| 现状流程图 | 一条直线「开始 → … → 结束」 | 起止 + **判定节点与分支**（是/否）+ 异常点标注 | 现状流程图含判定/分支 |
| 查检表 | 只有类别与频次 | 判定标准 + 收集期间 + 样本量 + 收集方法 + 责任人 + **记录方式** + 合计行 | 查检表判定标准/收集期间/样本量 |
| 数据汇总与层别 | 只列前几名类别 + 「其他」 | 类别**完整**列示（含合计）；层别维度**完整**列示并给出层别结论 | 数据汇总 / 层别分析维度 |
| 柏拉图 | 用样本量当分母做占比 | 降序 + 频次 + 累计百分比 + 80% 线；占比分母＝**缺陷合计**，现况值分母＝检查总数 | 缺陷合计不超过检查总数 |
| 目标设定 | 只给一个目标值 | 现况值/改善重点/圈能力 + 公式 + 现况 vs 目标对比图 + 合理性说明（圈能力要有出处） | 目标柱状图 / 对比图 |
| 鱼骨图 | 只画 4 个维度、每维 1 条要因 | **5M1E 六维**（人/机/料/法/环/测）+ 每维候选要因；只产生候选，不下结论 | 鱼骨图 5M1E/6M ≥5 维 |
| 要因评价 | 用一行文字写分数 | **逐维度评分列**（影响度/发生频次/可控性等）+ 总分 + 筛选阈值与结论 | 要因评价逐维度可见 |
| 真因验证 | 只写「成立」 | 要因/数据来源/验证方法/验证结果/结论 + **判定标准** + 不成立项回退说明 | 真因验证（来源/结果/结论） |
| 对策评价矩阵 | 把 4 个维度压成一格 | **逐维度评分列** + 总分 + 采纳/舍弃判定 | 对策评价逐维度可见 |
| 5W1H | 只有 5W，没有 How | What/Why/Who/Where/When/How + 对策↔真因映射 | 5W1H 六要素 |
| 对策实施与检讨 | 按阶段写几行进展 | **逐条对策**记录（对策/时间/责任人/实施内容/过程数据/困难与调整）+ 进展与完成率 | 逐条对策实施记录 |
| 效果确认（有形） | 只有改善后数字 | 改善前后对比图 + 目标达成率 + 进步率 + 统计检验或豁免 + **效益核算**（投入/收益/回收期） | 改善前后对比图 / 效益核算 |
| 效果确认（无形） | 用项目指标（如自动化水平）代替圈员能力 | **圈员能力维度 ≥5**（问题意识/数据分析/团队协作/表达沟通/工具应用/责任心…）+ 量表 + 前后均值 | 无形成果用圈员能力维度 |
| 标准化 | 只写「已标准化」 | 文件名称/类型/编号/版本/生效日期 + 稽核人/频率/方式 + 教育训练 + 效果维持 | 标准化文件编号/版本/生效日期 |
| 检讨与改进 | 只写下期主题 | 优点 / 不足 / 残余问题 / 下期主题 四项齐备 | 优点 / 不足 / 残余问题 / 下期主题 |

共同原则：**方法的结构必须能被读出来**——评分要逐维度可读，排程要逐项可读，
流程要有分支，成果要有前后对照。凡是把多维信息压成一格、或只写方法名称的页面，
一律按 `WEAK` 处理。

### 活动计划甘特图的最低要求（v5.6.2 补充）

`活动计划｜甘特图` 页必须是**工作项目排程**，不是阶段里程碑条：

1. **行**＝十步法工作项目（至少 6 行，建议十行全列），可按 P/D/C/A 分组并标注；
2. **列**＝时间轴（周次为主；活动周期不足两周时用日期），必须有列标题；
3. **每行含**：工作项目名、负责人、计划条、实际条；
4. **另设一列或一段**写明进度偏差（完成率 / 偏差天数 / 延期或提前的原因）；
5. 实际条必须能指回证据（例如文件时间戳、运行记录），不得与计划条同一来源；
6. 反例（判 `WEAK`）：只有「P 第1-2周 / D 第3-5周 / C 第6周 / A 第7周」四条阶段横条，
   或只有一段文字描述而没有逐行排程。

机器判定：`check_qcc_method_compliance.py` 的「工作项目 ≥6」规则会检查计划页是否
逐行列出十步法工作项；阶段条写法会被判 `WEAK`。

当使用 skill 自带模板（`qcc-empty-template.pptx` / `template_light_16_9.pptx`）或用户模板时：

1. **保留模板的封面、目录、结束页与母版背景**；背景、母版图片和主题色不得替换。
2. 正文页沿用模板的**配色、字体、标题样式与卡片语汇**（标题 + 短下划线 + 说明行 + 指标卡 + 结论条）。
3. **不得把模板里的占位小框当作正文容器**：模板占位框的尺寸对应标签、数值或短句；
   向其中填入长句会造成文字挤压、自动缩小与版式错乱。
4. 填充模板页时按**语义映射**：标题框只放标题，数值框只放数值，说明框只放短句；
   当内容与既有框位不匹配时，改用模板版式重建该页，而不是硬塞。
5. 交付前必须做渲染复核（截图/PDF）与格式审计；出现挤压、重叠、字号异常即判为不通过。
