# QCC Methodology for Achievement PPTs

QCC is not a generic engineering project report. A QCC presentation must prove a quality improvement loop.

## Core QCC flow

1. Circle introduction
2. Topic selection
3. Current-state investigation
4. Target setting
5. Cause analysis
6. Key factor confirmation
7. Countermeasure formulation
8. Countermeasure implementation
9. Effect confirmation
10. Standardization
11. Promotion and next step

## What each stage must answer

| Stage | Must answer |
|---|---|
| Circle introduction | Who did the activity, how roles were assigned, what evidence each role owns, and how the team operated. |
| Topic selection | Why this topic was selected over alternatives. |
| Current-state investigation | What the baseline problem is and how it is evidenced. |
| Target setting | What measurable target is set and why it is reasonable. |
| Cause analysis | What possible causes explain the current state. |
| Key factor confirmation | Which causes are confirmed by data or engineering constraints. |
| Countermeasure formulation | Which countermeasure maps to which confirmed factor. |
| Implementation | What was implemented and how it addresses the key factor. |
| Effect confirmation | Before/after results with evidence. |
| Standardization | How the improvement is made repeatable and how rebound is prevented. |
| Promotion | How the result moves from demo to shadow mode, pilot, and rollout. |

## Circle profile page purpose

The circle profile page is not a decorative member list. It must establish credibility:

- circle name and topic;
- activity cycle;
- leader, facilitator, members, and responsibilities;
- evidence responsibility, such as test owner, experiment owner, report owner;
- activity mechanism, such as weekly review, data confirmation, and acceptance baseline;
- standardization outputs.

## Technical QCC translation

| Technical fact | QCC expression |
|---|---|
| Adaptive controller implemented | Countermeasure implemented. |
| SafetyGate added | Risk prevention and quality control point established. |
| JSONL evidence generated | Traceable evidence chain standardized. |
| 646 tests passed | Verification system established. |
| Queue rebuild and replay | Key technical obstacle resolved. |

## v2.9 Mandatory QCC method mapping

A baseline QCC deck must not compress required QCC methods into generic narrative pages. The following method chain is mandatory for ordinary Agent generation:

| QCC phase | Required method page | Required visual form |
|---|---|---|
| 主题评审 | 头脑风暴 | Left topic anchor + 2×3 idea cards. No scoring. No loose radial connector clutter. |
| 主题评审 | 亲和图 | Clustered cards with group labels. |
| 主题评审 | 检查表 | Criteria scoring table or matrix; TOP summary card must not wrap scores. |
| 把握现状 | SIPOC | Supplier / Input / Process / Output / Customer table. |
| 把握现状 | 柏拉图 | Descending bars + cumulative percentage + 80% marker. |
| 把握现状 | 子流程图 | Flowchart or subprocess cards; pain points marked. |
| 根因分析 | 鱼骨图 | Fishbone branches; categories must converge to key governance gap. |
| 根因分析 | 矩阵图 | Cause scoring matrix with keep/discard result. |
| 根因分析 | 根因验证 | Evidence table/cards with method, evidence, result, conclusion. |
| 拟定对策 / 实施 | 5W | What / Why / Who / When / Where table or cards. |
| 成果固化 | 标准化清单 / 列表 | Checklist of standardized assets and follow-up checks. |

### Rule for lower-capability agents

When unsure, prefer method recognizability over visual creativity. A reviewer should identify the method from the page title and layout within three seconds.
